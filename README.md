# Онтологическая модель учебного процесса кафедры

Веб-приложение для описания и проверки четырёх видов учебных процессов: **практика, проведение дисциплины, выпускная квалификационная работа (ВКР) и учебное поручение**. Для каждого процесса создаётся карточка: например, для практики в ней указывают руководителя, срок сдачи отчёта, дату фактической сдачи и дату защиты.

Приложение представляет сведения в виде графа и объясняет результат каждого правила: **выполнено**, **нарушено** или **недостаточно данных**. Например, если отчёт требовалось сдать 15 октября, а сдали его 17-го, срок нарушен. Если дата защиты не указана, определить, был ли отчёт сдан до защиты, нельзя. Профиль и примеры демонстрационные: правила не являются утверждённым регламентом кафедры.

## Быстрый запуск на macOS и Windows

Установите Git и Node.js версии **22.13 или новее** с npm. В Terminal или PowerShell выполните:

```sh
git clone https://github.com/anton-ableton/ontology-builder.git
cd ontology-builder
npm run setup
npm start
```

Откройте **[http://127.0.0.1:8080/](http://127.0.0.1:8080/)**. Для первого знакомства не нужны языковая модель, ключ API или файл `.env`. В разделе «Практика» очистите поле «Руководитель»: явное «не назначен» сменится отсутствием сведений, и результат проверки изменится с «Нарушено» на «Недостаточно данных».

Если репозиторий уже скачан, выполняйте команды npm из его корня. `npm run setup` устанавливает зависимости сервера и клиента по lock-файлам и собирает интерфейс. При следующих запусках достаточно `npm start`; для остановки нажмите Ctrl+C. На другом компьютере запустите установку заново.

## Что умеет приложение

| Возможность | Результат |
| --- | --- |
| Вести карточки | Можно открыть пример, создать собственный процесс, изменить факты и увидеть пересчёт правил. Карточки сохраняются в текущем браузере. |
| Проверять требования | Программа проверяет назначения, наличие документа и порядок дат по правилам выбранного процесса. Рядом с выводом указано, на каких фактах он основан или каких сведений не хватает. |
| Переносить данные | Карточка в JSON открывается на другом компьютере вместе с подтверждёнными цитатами. Экспорт в Turtle (`.ttl`) содержит схему RDF/OWL и факты выбранного процесса. |
| Извлекать факты с помощью LLM | Из текста или PDF с текстовым слоем модель предлагает значения полей с цитатами. Пользователь выбирает, какие применить. На вход подаётся фрагмент до 4000 символов об одном процессе. |
| Исследовать понятия из PDF | Отдельный режим предлагает классы и отношения для черновика онтологии и экспортирует их в OWL. Рабочий профиль кафедры при этом не меняется. |

## Подключение языковой модели

LLM нужна только для извлечения из текста и PDF. Проверка правил, ручной ввод и экспорт работают без неё.

**Локально через Ollama.** Установите [Ollama](https://ollama.com/download), запустите её и скачайте модель:

```sh
ollama pull llama3.2:3b
ollama list
```

По умолчанию сервер обращается к `llama3.2:3b` по адресу `http://127.0.0.1:11434`. Если Ollama не запущена как приложение, выполните `ollama serve` в отдельном терминале. Выбрать другую установленную модель можно через `OLLAMA_MODEL`.

**Облако через OpenRouter.** Скопируйте [.env.example](.env.example) в `.env` в корне проекта. На macOS: `cp .env.example .env`; в PowerShell: `Copy-Item .env.example .env`. Если файл уже есть, отредактируйте его. Для облачного режима задайте:

```dotenv
LLM_PROVIDER=openrouter
OPENROUTER_MODEL=openrouter/free
OPENROUTER_API_KEY=ваш_ключ
```

Перезапустите сервер. Выбранный текст будет отправлен в OpenRouter. Поддерживаются [бесплатный маршрутизатор](https://openrouter.ai/openrouter/free) и явные идентификаторы моделей с окончанием `:free`. Чтобы вернуть локальную модель, смените `LLM_PROVIDER` на `ollama` и снова перезапустите сервер. Ключ остаётся на сервере; `.env` исключён из Git.

## Устройство проекта

- [Профиль кафедры](backend/src/domain/department.json) задаёт классы, поля, отношения и правила. [Схема в Turtle](model/department.ttl) доступна отдельно. После изменения профиля пересоберите её командой `npm run ontology`.
- [Модуль проверки](backend/src/domain/model.js) строит граф из фактов и применяет к нему правила профиля. Это прикладные проверки на JavaScript. Один экземпляр процесса занимает одну карточку; каждое поле хранит одно значение.
- [Модуль LLM](backend/src/llm/) отвечает за подключение провайдера, формирование промпта из профиля и проверку предложенных значений по тексту источника. [Интерфейс на React](frontend/src/features/) показывает карточки, граф и объяснения.
- Файлы в `data/outputs/` относятся к раннему эксперименту по извлечению онтологий из статей. Рабочая модель кафедры находится в `model/`.

## Разработка и проверка

После `npm run setup` доступны следующие команды:

| Команда из корня | Назначение |
| --- | --- |
| `npm test` | Проверить правила, граф, экспорт и фильтрацию предложений без LLM. |
| `npm run smoke` | Запустить временный сервер и проверить собранный интерфейс, API и чтение PDF. |
| `npm --prefix frontend run lint` | Проверить код интерфейса. |
| `npm run demo` | Вывести результаты проверки демонстрационных карточек в терминал. |
| `npm run eval:llm` | Вызвать активную модель и сравнить предложения с размеченными синтетическими примерами. В облачном режиме расходуется квота. |

Для разработки запустите сервер через `npm --prefix backend run dev`, а в другом терминале — `npm --prefix frontend run dev`. Для проверки сборки используйте `npm run build`. [Результаты локальной оценки Llama](docs/validation.json) относятся к синтетическим фрагментам; качество на реальных документах кафедры требует отдельной проверки.
